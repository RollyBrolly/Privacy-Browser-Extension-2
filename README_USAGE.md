# Privacy Breach Detection Extension — Setup and Usage Guide

## 1. Requirements

On the computer that will run the extension, install:

* Python 3.10 or newer
* Google Chrome
* An internet connection for installing Python packages

Visual Studio Code is optional. These steps use Windows PowerShell.

## 2. Project Setup

Copy or extract the **entire** `baby-caps` project folder onto the other
computer. Keep its folder structure intact. Include the `dataset` folder and,
if you want to reuse the trained models, all three files in `model`. Do not
copy `.venv`; virtual environments are specific to the computer that created
them and will be recreated below.

The folder should have this structure. Model files may be generated by the
training commands if they were not copied:

baby-caps/
├── dataset/
│   ├── privacy_dataset.csv
│   └── pii-masking-200k.csv
├── model/
│   ├── privacy_model.pkl
│   ├── tfidf_vectorizer.pkl
│   └── pii_entity_model.pkl
├── extension/
├── train_model.py
├── train_pii_model.py
├── pii_detection.py
├── app.py
├── README.md
└── README_USAGE.md

## 3. Create and Activate the Python Virtual Environment

Open PowerShell in the `baby-caps` project folder and create a new environment:

### Windows PowerShell

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, use
`.\.venv\Scripts\python.exe` instead of `python` in the commands below.

## 4. Install Required Packages

With the environment active, install the packages:

```powershell
python -m pip install --upgrade pip
python -m pip install pandas scikit-learn joblib flask flask-cors
```


## 5. Train Both Models

If the copied `model` folder contains `privacy_model.pkl`,
`tfidf_vectorizer.pkl`, and `pii_entity_model.pkl`, you can try using those
artifacts without retraining. If they are missing or fail to load, train the
models on this computer. Retraining also avoids compatibility issues between
different scikit-learn versions.

From the project root with the virtual environment active, run these in order
to create fresh model files:

```powershell
python train_model.py
python train_pii_model.py
```

It reads `dataset/privacy_dataset.csv`, requires `text` and `label`, and saves:

```text
model/privacy_model.pkl
model/tfidf_vectorizer.pkl
```

It reads `dataset/pii-masking-200k.csv`, using `unmasked_text` and
`span_labels`, skips invalid span annotations, and reports held-out token
metrics. These are token-level measurements, not whole-entity or real-page
accuracy. It saves `model/pii_entity_model.pkl`.

Do not run `pii_detection.py` directly; the trainer and API import it as a
helper. If all three compatible model files were copied, you can skip both
training commands. Retrain if files are missing or fail to load.

Before starting the API, confirm the model directory contains:

model/
├── privacy_model.pkl
├── tfidf_vectorizer.pkl
└── pii_entity_model.pkl

The API loads model files at startup. Restart `app.py` after retraining so it
uses the new artifacts.


## 6. Start the Python API

From the project root, with the virtual environment active:

```powershell
python app.py
```

The API should start on:

http://127.0.0.1:5000

Keep this terminal open while testing the browser extension.
Chrome and the Flask API must run on the same computer because the extension
connects to `127.0.0.1` on that computer.

## 7. Test the API

Open Chrome and visit:

http://127.0.0.1:5000/


A successful response should look like:

```json
{
       "status": "running",
       "service": "Privacy Breach Detection API",
       "models": [
              "TF-IDF + Logistic Regression risk classifier",
              "PII token detector"
       ]
}
```

If Chrome displays:

ERR_CONNECTION_REFUSED

make sure `python app.py` is still running.


## 8. Load the Chrome Extension

Open Chrome and enter:

chrome://extensions/


Then:

1. Turn on **Developer mode**.
2. Select **Load unpacked**.
3. Select the project's `extension` folder.
4. Confirm that **Privacy Risk Detector** appears.
5. Pin the extension if desired.

The selected folder should contain:

extension/
├── manifest.json
├── content.js
├── popup.html
├── popup.js
└── style.css

## 9. Test Webpage Scanning

Open a normal webpage.

Do not test initially on Chrome internal pages such as:


chrome://extensions/
chrome://settings/
chrome://history/


Open a normal website instead.

Refresh the webpage after reloading the extension.

Then:

1. Click the Privacy Risk Detector extension.
2. Click **Scan This Page**.
3. The extension reads up to 50,000 characters of visible page text, form
       metadata, and external-resource metadata.
4. It sends that information to the local API at `127.0.0.1:5000`.
5. The popup displays the risk label, indicator score, model confidence,
       sensitive form fields, text-based indicators, and grouped PII detections.


## 10. Current Expected Result

The popup displays a classification such as:

LOW - Privacy Risk
Indicator score: [heuristic value]
Model confidence: [class probability]% for LOW

or:

MEDIUM - Privacy Risk
Indicator score: [heuristic value]
Model confidence: [class probability]% for MEDIUM


The indicator score is a heuristic and is not guaranteed to increase with the
LOW/MEDIUM/HIGH label. Model confidence is the probability assigned to the
selected class; it is not a guarantee that the page is safe or unsafe. Neither
value is a calibrated real-world privacy-risk measurement.


## 11. What the Detectors Check

The extension scans only after **Scan This Page** is clicked. Its checks are:

* The risk classifier predicts LOW, MEDIUM, or HIGH from page title and text.
* Collection indicators look for request phrases such as `enter your` and
  `provide your` in visible text.
* Tracking indicators look for terms such as `cookies`, `tracking`, and
  `analytics` in visible text. They do not verify actual network tracking.
* Form analysis inspects each form field's input type, autocomplete token,
  label, placeholder, accessible label (`aria-label`/`aria-labelledby`),
  instructions (`aria-describedby` and helper text), and the form's purpose
  (label, `legend`, or nearest heading) to decide whether the page actually
  asks for email, phone, password, payment, government ID, and similar data.
  Fields outside any `<form>` element and forms that submit to a different
  domain are also flagged.
* Form-confirmed collection is scored much more heavily than keywords that
  only appear in visible page text. The popup separates "Data This Page Asks
  For" from "Sensitive Terms in Page Text" so an article that merely mentions
  the word "password" is not reported the same way as a field that collects
  one.
* The PII model returns generic spans; email, phone, and IPv4 patterns have
  separate checks. The popup hides matched values and groups detections.

These are heuristic and model-based signals, not proof that a site is safe or
unsafe. Keyword matches do not establish actual cookies, network requests, or
data transfers.

## 13. Troubleshooting

### `Import "pandas" could not be resolved`

Install Pandas:


pip install pandas


Make sure VS Code is using the correct Python interpreter.


### `ParserError` when loading the CSV

Check that:

dataset/privacy_dataset.csv


is a valid CSV with the expected columns:


text,label


### `ERR_FILE_NOT_FOUND`

Check that `popup.html` exists inside:

extension/


The manifest contains:

```json
"default_popup": "popup.html"
```

Therefore, `popup.html` must be in the same directory as `manifest.json`.


### `Could not establish connection. Receiving end does not exist.`

Reload the extension at:


chrome://extensions/


Then refresh the webpage being tested.

The webpage should be a normal website, not a Chrome internal page.



### `ERR_CONNECTION_REFUSED`

Make sure the Flask API is running:


python app.py


Then test:

http://127.0.0.1:5000/


## 14. Data Handling

Scanned page text, form metadata, and external-resource metadata are sent to
the Flask service on this computer at `127.0.0.1:5000`. The extension does not
send these values to a remote project server. It saves the scanned URL, risk
label, indicator score, confidence, and timestamp in Chrome local storage; it
does not save the scanned page text there. Avoid testing with real sensitive
information.

## 15. Development and Evaluation Limitations

The risk dataset contains 90 rows, including 72 synthetic examples. A random
20% split tests on only 18 rows; its current accuracy is a development check,
not a reliable real-world performance estimate. Use independently collected
and labeled examples plus a separate representative test set before reporting
final results.

The PII model's reported precision, recall, and F1 are token-level metrics.
They do not directly measure whole-entity detection or performance on
real-world webpages. Review false positives and missed detections manually.
